# Contribution & Publication Policy

Этот репозиторий является **публичной учебной базой знаний по Software Engineering**.

Главная цель политики — сохранить техническое содержание полезным и одновременно исключить попадание в публичный репозиторий приватной или персональной информации.

## Privacy boundary — граница приватности

В `SoftwareEngineeringBase` **нельзя публиковать**:

- персональные данные владельца репозитория;
- сведения из приватных разговоров, если владелец явно не попросил опубликовать конкретный фрагмент;
- содержимое, код, архитектуру, названия внутренних сущностей или бизнес-логику из private repositories;
- приватные файлы, токены, ключи, секреты, credentials и конфигурацию;
- информацию о семье, местоположении, здоровье, личной жизни или других личных обстоятельствах;
- любые сведения, которые позволяют восстановить закрытый контекст по косвенным признакам.

## Allowed sources — допустимые источники

Для публичных материалов разрешены:

- общие знания по программированию и Software Engineering;
- публичная техническая документация и другие допустимые открытые источники;
- нейтральные учебные примеры, специально созданные для этой базы;
- уже опубликованное содержимое самого `SoftwareEngineeringBase`;
- конкретный материал, который владелец **явно разрешил опубликовать в этом репозитории**.

Если для объяснения нужен пример, связанный с приватным проектом, он должен быть заменён на нейтральную модель, например `Order`, `Payment`, `User`, `Product`, а не копироваться из закрытого кода.

## Publication rule

Перед публикацией новый материал должен проходить простую проверку:

```text
Source material
      ↓
Is it public or explicitly approved?
      ↓ yes
Remove personal/private context
      ↓
Use neutral examples where possible
      ↓
Publish to SoftwareEngineeringBase
```

Если источник или право на публикацию вызывают сомнение — материал **не публикуется** до явного разрешения владельца.

## External contributions

Публичность репозитория не означает право изменять его напрямую.

Внешние участники могут предлагать изменения через **fork + Pull Request**, но решение о принятии изменений остаётся за владельцем репозитория.

Не следует запрашивать или предоставлять внешним участникам write/admin access только ради предложения исправления.

Любой Pull Request, содержащий персональные данные, приватный код, secrets или сведения из закрытых источников, должен быть отклонён.

## Core principle

> **Public knowledge only. Private context stays private unless the owner explicitly approves publication of specific material.**
