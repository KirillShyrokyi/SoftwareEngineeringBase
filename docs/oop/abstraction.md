# Abstraction

> Save Point: базовое понимание абстракции в OOP и её отличие от инкапсуляции.

## Главная идея

**Abstraction / абстракция** — это выделение существенного на текущем уровне и сокрытие ненужных для него деталей реализации.

Короткая модель:

> **Абстракция позволяет работать с понятной операцией, не думая о том, как именно она выполняется внутри.**

Абстракция не уничтожает сложность. Низкоуровневые действия всё равно существуют и выполняются, но вызывающему коду не обязательно о них знать.

## Высокий и низкий уровни

Например, пользователь хочет сохранить документ.

На высоком уровне ему нужна одна операция:

```text
Сохранить документ
```

Внутри для этого могут потребоваться более низкоуровневые действия:

```text
Сохранить документ
        ↓
преобразовать данные
        ↓
закодировать данные
        ↓
открыть файл
        ↓
записать байты
        ↓
закрыть файл
```

Пользователю операции `Save` не нужно самостоятельно управлять каждым из этих шагов.

В коде идея может выглядеть так:

```csharp
public class DocumentStorage
{
    public void Save(string text)
    {
        // технические шаги сохранения
    }
}
```

Внешний код работает на более высоком уровне:

```csharp
storage.Save("Hello");
```

## Абстракция не зависит от количества методов

Если реализация `Print()` занимает 500 строк и не разбита на маленькие вспомогательные методы, абстракция для вызывающего кода не исчезает:

```csharp
printer.Print(document);
```

Снаружи всё ещё существует одна понятная операция высокого уровня — «напечатать документ».

Разбиение реализации на небольшие методы может улучшить читаемость и устройство внутреннего кода, но само по себе не определяет наличие абстракции.

## Абстракция и инкапсуляция

Эти понятия связаны, но отвечают на разные вопросы.

**Абстракция:**

> Что мне действительно нужно знать и использовать на этом уровне?

Например, `Save()` позволяет не думать о деталях файловой системы и записи данных.

**Encapsulation / инкапсуляция:**

> Кто может обращаться к внутреннему состоянию и каким способом?

Инкапсуляция защищает внутреннее состояние и задаёт контролируемые способы взаимодействия с ним.

Полезное различие:

```text
Абстракция
└── мне НЕ НУЖНО знать ненужные детали

Инкапсуляция
└── я НЕ МОГУ произвольно обращаться с внутренним состоянием
    и должен работать через предусмотренные правила
```

## `private` и абстракция — не одно и то же

`private` — модификатор доступа и один из механизмов, используемых для инкапсуляции.

Наличие `private` само по себе не создаёт абстракцию. И наоборот, высокоуровневая абстракция может существовать даже без `private`: например, вызывающий код может использовать понятную операцию `Save()`, не разбираясь в технических шагах её выполнения.

## Mental model

```text
Низкий уровень
└── множество технических деталей
        ↓
     абстрагируем
        ↓
Высокий уровень
└── понятная существенная операция
```

Примеры:

```text
запустить стартер + проверить топливо + ...
→ Start()

подготовить данные + записать байты + ...
→ Save()

подготовить документ + отправить данные принтеру + ...
→ Print()
```

Главная мысль:

> **Абстракция не убирает сложность — она позволяет не думать о ней на более высоком уровне.**

## Проверка понимания

Тема считается понятой, если можно объяснить следующее:

- `Save()` или `Print()` могут предоставлять высокоуровневую абстракцию над множеством технических шагов;
- детали реализации продолжают существовать, даже если вызывающий код их не видит;
- 500 строк внутри одного `Print()` не уничтожают абстракцию для внешнего кода;
- `private` не равен абстракции;
- абстракция и инкапсуляция могут существовать независимо;
- абстракция отвечает прежде всего за существенное представление операции, а инкапсуляция — за контроль доступа к внутреннему состоянию и внутренним деталям.
