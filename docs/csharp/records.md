# Records — сравнение данных и изменённые копии

[← C#](index.md) · [Roadmap](../roadmap.md)

## Зачем нужен record

Обычный `class` по умолчанию сравнивает ссылки. Для модели данных иногда важно сравнивать содержимое: две независимо созданные записи с одинаковыми значениями должны быть равны.

`record User(string Name, int Age);` объявляет отдельный тип `record class` (ссылочный тип). В этой краткой форме C# создаёт конструктор и свойства `Name`, `Age`.

```csharp
record User(string Name, int Age);

User first = new("Alex", 20);
User second = new("Alex", 20);
Console.WriteLine(first == second); // True
```

Это *value equality*: для такого record сравниваются значения, хотя `new` создал два объекта. Для обычного класса без перегрузки `==` те же два отдельных объекта дали бы `false`.

## Ссылки и копирование

```csharp
User same = first; // копируется ссылка; новый объект не создаётся
User changed = first with { Age = 25 };
```

`with` создаёт новую запись на основе исходной, меняя указанные свойства. `first.Age` остаётся `20`, а `changed.Age` равно `25`. Это *non-destructive mutation*; при этом копирование поверхностное (*shallow copy*), и ссылочные вложенные значения могут остаться общими.

```csharp
User restored = changed with { Age = 20 };
Console.WriteLine(first == changed);  // False
Console.WriteLine(first == restored); // True
```

Несмотря на разные объекты, `first` и `restored` равны по значениям.

## Разновидности

`record User(...)` — это `record class` (reference type). `record struct Point(int X, int Y)` объявляет value type. Оба варианта являются объявлениями типов, а не полями внутри другого класса.

## Рабочая модель

```text
class:  обычно сравнение ссылок
record: сравнение содержимого по значениям
with:   создание изменённой копии без изменения исходной записи
```

Record особенно удобен для моделей данных, где важны значения и создание копий с отдельными изменениями. Он не означает, что любые вложенные объекты автоматически становятся неизменяемыми.
